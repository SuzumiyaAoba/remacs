修飾付き特殊キーをフロントエンドから送ると、登録済みのキーバインドに一致しません。実 GUI の C-Home が `C-<home> is undefined` となり、point が移動しないことを確認しました。

対象 HEAD: `29e7c960edec18a99107741c351d95444f8f6b18`。

## 再現

1. GUI で複数行のテキストを開き、末尾へ移動する。
2. C-Home を押す。
3. `C-<home> is undefined` と表示され、point が末尾のままになる。

`(key-binding [C-home])` は GNU と remacs の両方で `beginning-of-buffer` を返すため、バインドの欠落ではありません。

公開された `term::dispatch_key_core` にフロントエンドと同じコードを渡した個別実行でも、次の結果でした。

```text
C-home binding: beginning-of-buffer
C-home actual: (9 "C-<home> is undefined")
Home control: 1
```

初期内容は `alpha`、改行、`beta`、point は 9。C-Home では 1 へ移動すべきところ 9 のままです。修飾なし Home の対照ケースは処理されます。

## 原因候補

GUI の `keystroke_to_code` と TUI の `key_event_to_code` は `event_code_for("home") | CHAR_CTL` を送ります。一方、キーマップの `key_seq_elt` は修飾付きシンボル全体 `"C-home"` を `event_code_for` に渡します。名前全体のハッシュと、基底名ハッシュに modifier bit を付けたコードが異なるため一致しません。共有 dispatch 経路で再現し、両フロントエンドに同じ構成処理があります。
