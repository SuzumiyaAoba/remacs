macOS の実 GUI で ASCII は入力・保存できる一方、同じ入力経路から Unicode 文字を入力すると失われます。

対象 HEAD: `29e7c960edec18a99107741c351d95444f8f6b18`。`target/debug/remacs` を実 GUI として起動して確認しました。

## 再現手順

1. GUI を起動し、`C-x C-f` で一時ファイルを開く。
2. 通常の文字入力で `alpha beta`、改行、`second line` を入力し、`C-x C-s` で保存する。これは成功する。
3. 空行に macOS の Unicode テキスト入力で `日本語` を入力し、保存する。今回は UI 自動操作の `typeText` を使用。
4. 続けて同じ方法で `A日B` を入力し、保存してファイルを読み取る。

期待値は `日本語A日B` だが、実際に保存された行は `AB` だった。ASCII の A/B だけが残り、日本語文字が全て失われた。繰り返しても同じ結果になった。

通常のファイルオープン・ASCII 編集・保存・インクリメンタル検索・上下分割・分割解除・終了は、同じ GUI セッションで動作した。

## 調査箇所

`src/gui.rs` の EditorView は `.on_key_down` でキーを送る実装で、OS が確定したテキストを渡す InputHandler の実装・登録がない。キーイベント以外で確定される文字が届かないことが原因候補。日本語 IME の変換操作そのものの検証は別途必要だが、本件の Unicode 入力の欠落はファイル内容で確認済み。
