parse-sexp-lookup-properties=t のバッファで一つの . だけに word 構文の属性を付けると、GNU の \w+ はその位置を単語の一部として扱い、\b もその境界に一致しない。remacs は属性を無視する。属性付き文字列を string-match する場合も同じ。通常の syntax table の変更と、属性を無効にしたバッファの対照ケースは一致する。re_syntax が文字単位の静的なテーブル参照だけを返し、位置ごとの syntax-table 属性を見ていない。既存 #8 の POSIX 文字クラスの定義差とは別に、通常の \w / \b で再現する。

対象: `29e7c960edec18a99107741c351d95444f8f6b18` / macOS / GNU Emacs 31.1 との同一再現コードによる比較。
