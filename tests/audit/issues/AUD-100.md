(a) (b) を供給する関数ストリームで read すると、GNU は (a) だけを読み、次の read で (b) を返す。remacs は最初の read で残りも全て消費し、次は end-of-file になる。数値の後の先読み文字を戻す一引数の呼び出しも行わない。関数から全入力を String へ集めた後で一式を解析する実装になっている。#92 の標準入力の未実装とは別のストリーム処理の問題。

対象: `29e7c960edec18a99107741c351d95444f8f6b18` / macOS / GNU Emacs 31.1 との同一再現コードによる比較。
