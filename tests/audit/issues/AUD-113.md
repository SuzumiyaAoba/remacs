STRING 引数付きの replace-match で、元の a/c と置換する X に別々の face を付けると、GNU は全て保持するが remacs は全て nil にする。バッファへの置換と replace-regexp-in-string 経由でも、置換する X の属性が失われる。match-string で属性を取り出す対照ケースは一致する。また unibyte の (128 97 255) を文字列として置換すると、replace-match は (4194176 88 4194303) を返し、GNU の (128 88 255) と異なる。置換文字列や結果を属性・バイト表現の情報なしの String として扱っている。

対象: `29e7c960edec18a99107741c351d95444f8f6b18` / macOS / GNU Emacs 31.1 との同一再現コードによる比較。
