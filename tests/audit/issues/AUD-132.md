選択ウィンドウを高さ4にして他に広いウィンドウを残しても、display-buffer は選択ウィンドウの split-window エラーを伝播し表示できない。GNU は他の表示先を選んで成功する。また list-buffers で作ったバッファを毎回 kill しながら4回呼ぶケースでも、remacs は分割を増やして途中で同じエラーになる。これが qa_buffmenu の失敗原因で、最新CLIでも再現した。明示的な display-buffer-use-some-window アクションでは成功する。prelude のフォールバックが split-window を無条件に呼び、分割不能時に次の候補へ進まない。#47 は split-window 自体の最小サイズ検査であり、本件は正しい分割拒否の後に表示先を探さない別の問題。

対象: `29e7c960edec18a99107741c351d95444f8f6b18` / macOS / GNU Emacs 31.1 との同一再現コードによる比較。
