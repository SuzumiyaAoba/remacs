unibyte の 233 と multibyte の 256 の比較は GNU では前者が小さいが、remacs は逆になる。同じ数値 233 の unibyte/multibyte の組では、GNU はどちらも小さいと判定しないが remacs は multibyte 側が小さいと判定する。string= と compare-strings の対照結果は一致しており、string-lessp が Rust の内部文字列の大小を直接比較している経路の問題。

対象: `29e7c960edec18a99107741c351d95444f8f6b18` / macOS / GNU Emacs 31.1 との同一再現コードによる比較。
