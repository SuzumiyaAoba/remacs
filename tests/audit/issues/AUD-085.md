元のマークが未設定のとき、内部で set-mark すると save-mark-and-excursion を抜けても新しいマークと mark-active=t が残る。GNU は元の未設定・非アクティブ状態へ戻す。また元から存在したマークを再アクティブ化する際、GNU が実行する activate-mark-hook の呼び出しが一回不足する。Rust の excursion 復元経路は保存したマークが Some のときしか状態を復元せず、復元時の hook も実行しない。

対象: `29e7c960edec18a99107741c351d95444f8f6b18` / macOS / GNU Emacs 31.1 との同一再現コードによる比較。
