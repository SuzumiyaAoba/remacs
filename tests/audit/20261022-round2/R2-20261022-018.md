キーボードマクロの記録終了だけで、入力した内容がもう一度実行されます。終了時の繰り返し数は記録操作自体を最初の一回として数える必要があります。

## 実端末での再現

空のファイルを `-Q -nw` で開き、次を順に入力します。

```text
C-x (    記録開始
x        文字を一つ入力
C-x )    記録終了
C-x C-s  保存
```

GNU: `x\n`
Remacs: `xx\n`

記録終了後にさらに C-x e を一度実行した別の対照では、GNUは `xx\n`、Remacsは `xxx\n` でした。80×24の独立PTYで両側とも画面表示・保存・正常終了を確認しています。

原因候補: lisp/kmacro.el の kmacro-end-macro は `(interactive "p")` により通常呼び出しでも1を end-kbd-macro に渡します。src/editor/mod.rs の f_end_kbd_macro は非nilのREPEATをそのまま f_call_last_kbd_macro に渡し、さらに1回実行しています。GNUの仕様は「記録を最初の一回に含めた合計回数」で、通常の1では追加実行しません。

対象: `926cbfc7fe1ddde28c53d0555be1f6b99563535b` + 調査時の既存 shell/display 作業ツリー変更、macOS/aarch64、GNU Emacs 31.1。固定バイナリ SHA-256: `37aec7800115143d785086fa184114757237776c93c892e30696644b5c255017`。実PTYへのアクセスが必要なため、/dev/tty制限のない環境で比較しました。
