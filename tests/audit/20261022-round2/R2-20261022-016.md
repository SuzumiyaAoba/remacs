`--batch` を指定していない起動でも、`--eval` / `-l` / `-f` があると Remacs は編集ループに入らず終了コード0で終了します。GNU は指定した初期処理を行って編集画面を開き、そのまま動作し続けます。

## 再現

実端末でそれぞれ実行します。

```sh
./target/debug/remacs -Q -nw --eval '(setq audit-cli-startup t)'
./target/debug/remacs -Q -nw -f ignore
```

`(setq audit-cli-startup t)` だけの startup.el を作り、`-Q -nw -l startup.el` でも同じです。

80×24 の独立したPTYで比較した結果、GNUは3条件すべてscratchのフレームを表示し、C-x C-cを送るまで生存しました。Remacsは3条件すべてフレームなしで自然終了しました（exit_before_quit=0、約8〜10秒）。初期化オプションなしの `-Q -nw` は両方とも画面表示・終了に成功しています。

実際のファイル編集検査でも、同じファイル指定に --eval を付けるとRemacsだけ編集画面が開かず、オプションを外すと編集・保存できました。

原因候補: src/main.rs の batch_arg が --eval/--load/-l/-f/--funcall をGUI起動から除外し、その後のオプション処理でも batch=true にしています。これらは --batch を暗黙に指定するオプションではありません。

対象: `926cbfc7fe1ddde28c53d0555be1f6b99563535b` + 調査時の既存 shell/display 作業ツリー変更、macOS/aarch64、GNU Emacs 31.1。固定バイナリ SHA-256: `37aec7800115143d785086fa184114757237776c93c892e30696644b5c255017`。実PTYへのアクセスが必要なため、/dev/tty制限のない環境で比較しました。
