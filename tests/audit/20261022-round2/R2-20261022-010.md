内側の condition-case で処理されるはずのエラーに、外側の handler-bind が呼ばれます。そこで throw すると condition-case のハンドラが実行されず、正常なエラー処理が横取りされます。再 signal のケースでは外側の通知が二重に実行されます。

対象: `926cbfc7fe1ddde28c53d0555be1f6b99563535b` + 調査時の shell/display に関する既存作業ツリー変更、macOS/aarch64、GNU Emacs 31.1。現在のソースをビルドして固定したバイナリ SHA-256 `37aec7800115143d785086fa184114757237776c93c892e30696644b5c255017` で個別プロセス検証。

## 再現

以下を repro.el に保存します。

```elisp
;;; -*- lexical-binding: t; -*-

;; handler-order:outer-steals-caught-error
(prin1 (catch 'out (handler-bind ((error (lambda (_) (throw 'out 'stolen)))) (condition-case nil (error "audit") (error 'caught)))))
(terpri)

;; handler-order:inner-observer
(prin1 (let ((seen nil)) (list (condition-case nil (handler-bind ((error (lambda (_) (push 'observed seen)))) (error "audit")) (error 'caught)) seen)))
(terpri)

;; handler-order:resignal
(prin1 (let ((seen nil)) (list (condition-case nil (handler-bind ((error (lambda (_) (push 'observed seen)))) (condition-case err (error "audit") (error (signal (car err) (cdr err))))) (error 'caught)) seen)))
(terpri)
```

```sh
./target/debug/remacs -Q --batch -l repro.el
/path/to/emacs-31.1 -Q --batch -l repro.el
```

検証結果（ok は式の正常な戻り値）:

`handler-order:outer-steals-caught-error`

```text
GNU: (ok caught)
Remacs: (ok stolen)
```

`handler-order:inner-observer`

```text
GNU: (ok (caught (observed)))
Remacs: (ok (caught (observed)))
```

`handler-order:resignal`

```text
GNU: (ok (caught (observed)))
Remacs: (ok (caught (observed observed)))
```

原因候補: [src/lisp/eval.rs の offer_signal](https://github.com/SuzumiyaAoba/remacs/blob/926cbfc7fe1ddde28c53d0555be1f6b99563535b/src/lisp/eval.rs#L6436) が handler_bindings をすべて走査してから case_handlers を調べます。両者の動的な入れ子順序が表現されず、内側の捕捉で外側への通知を止められません。単純に condition-case が存在すると全 handler-bind を止める修正では、内側の observer が必要な対照ケースを壊します。
