空のバッファで org-mode を有効にするだけで `(void-function keyword)` になり、Org の編集を開始できません。GNU Emacs 31.1 では成功します。長めの起動時間によるタイムアウトと区別するため、180秒上限で単独再試行し、約69秒後に同じLispエラーを確認しました。font-lock のケースも約82秒で同じエラーです。

対象: `926cbfc7fe1ddde28c53d0555be1f6b99563535b` + 調査時の既存 shell/display 作業ツリー変更、macOS/aarch64。固定バイナリ SHA-256 `37aec7800115143d785086fa184114757237776c93c892e30696644b5c255017`。

## 利用者向けの再現

```sh
./target/debug/remacs -Q --batch --eval '(with-temp-buffer (org-mode) (princ major-mode))'
/path/to/emacs-31.1 -Q --batch --eval '(with-temp-buffer (org-mode) (princ major-mode))'
```

GNU は `org-mode`。Remacs は `void-function keyword`。

## 絞り込んだ再現

```elisp
(require 'org-element-ast)
(org-element-deferred-create-alias :raw-value)
```

GNU: `[org-element-deferred org-element-property-2 (:raw-value) nil]`
Remacs: `(void-function keyword)`

同じ値を直接構築する次の対照は両側で成功します。

```elisp
(require 'org-element-ast)
(org-element-deferred-create nil #'org-element-property-2 :raw-value)
```

## 失敗時のスタック

```text
org-element-deferred-create-alias(:raw-value)
(defconst org-element--headline-raw-value
  (org-element-deferred-create-alias :raw-value) ...)
load-with-code-conversion(.../lisp/org-element.el ...)
org-mode()
```

`require 'org` 自体は成功し、その後の org-mode が org-element をロードする段階で失敗します。

調査箇所: [lisp/org-element-ast.el:281](https://github.com/SuzumiyaAoba/remacs/blob/926cbfc7fe1ddde28c53d0555be1f6b99563535b/lisp/org-element-ast.el#L281)。GNU の &aux 付きコンストラクタを通常の defun に置き換えた移植用定義があります。この補助関数を funcall 経由にする実行時だけの対照では alias 自体は成功しましたが、続く org-mode は別の `void-function t` で失敗しました。コンストラクタ／ソース展開経路を含めて起動まで確認する必要があり、この差し替えを完成した修正とはしていません。

同じ BOA &rest 構造を使った縮小例は GNU のソースロードでも失敗するため、その縮小例だけを別の Rust 評価器バグとして数えていません。本件は配布されている Org が GNU では起動し、Remacs では起動しない問題です。
