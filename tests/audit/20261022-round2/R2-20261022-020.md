tests/qa.rs は emacs -Q --batch と同じ環境を作ると説明していますが、interp() による起動処理の後で i.noninteractive=true / (setq noninteractive t) を設定します。起動時に決まる transient-mark-mode 等の状態は既に対話用になっているため、qa_buffer2 と qa_mark が失敗します。

## 再現と切り分け

```sh
cargo test --offline --test qa qa_buffer2 -- --exact --nocapture
cargo test --offline --test qa qa_mark -- --exact --nocapture
```

通常の実行での例:

```text
FAIL (transient-mark-mode nil t)
FAIL ((region-active-p) nil t)
FAIL ((use-region-p) nil t)
```

同じコンパイル済みテストを、プロセス開始前に REMACS_NONINTERACTIVE=1 を設定して個別実行すると両方成功します。GNU Emacs 31.1 の -Q --batch -l qa_framework.el -l qa_buffer2.el / qa_mark.el も成功します。

```sh
REMACS_NONINTERACTIVE=1 cargo test --offline --test qa qa_buffer2 -- --exact --nocapture
REMACS_NONINTERACTIVE=1 cargo test --offline --test qa qa_mark -- --exact --nocapture
```

起動後にフラグを切り替えるのではなく、バッチ条件を指定して Interp を構築するハーネスが必要です。テスト内からプロセス全体の環境変数を書き換えると並列実行へ影響するため、構築時の条件指定として扱うのが妥当です。

環境: macOS/aarch64、調査時HEAD `aeaff5597e60834c21d464b7ad2a4caf167726dc`。全1,074テストの実行中に、QA369件のうち2件がこの条件で失敗しました。古い監査記録にも起動条件差として記録されていましたが、同じ問題の既存Issueは見つかりませんでした。

調査箇所: tests/qa.rs の run（16〜38行付近）、tests/common/mod.rs の interp、Interp の初期化時の noninteractive 判定。
