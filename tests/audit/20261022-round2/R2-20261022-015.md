default-file-modes を0400にした状態で TEXT="abc" を指定すると、GNU は作成時のファイル記述子で内容を書き込みますが、Remacs は内容が空のファイルを成功として返します。文字コード問題ではなく、ASCII の3文字でも発生するデータ消失です。

対象: `926cbfc7fe1ddde28c53d0555be1f6b99563535b` + 調査時の既存 shell/display 作業ツリー変更、macOS/aarch64。GNU Emacs 31.1 と固定バイナリ `37aec7800115143d785086fa184114757237776c93c892e30696644b5c255017` で個別実行。設定・一時ファイルは各ケースの unwind-protect で復元・削除しています。

結果の256は0400の十進表記です。

```text
公開 make-temp-file:
GNU:    (256 "abc")
Remacs: (256 "")

内部 make-temp-file-internal の対照:
GNU:    (256 "abc")
Remacs: (256 "abc")
```

原因候補: src/editor/mod.rs の f_make_temp_file は create_new で作った記述子を閉じ、TEXT を fs::write で再オープンして書きます。0400では再オープンが失敗しますが、その Result を捨ててファイル名を返しています。内部 make-temp-file-internal は作成済み記述子へ write_all するため成功します。

#326 の過剰に広い既定権限、#327 のバイト表現変換とは別の問題です。所有者限定の0600を指定するだけでは、呼び出し元が書き込みを制限する umask を設定した場合の再オープン失敗とエラー破棄は解決しません。
