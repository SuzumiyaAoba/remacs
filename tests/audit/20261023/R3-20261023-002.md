初期状態で `(require 'shortdoc-doc)` を評価すると、GNU Emacs 31.1 は成功しますが、Remacs は eager macro expansion の循環検出エラーになりロードできません。全テスト実行の `dumped_and_autoloaded_misc_libs2_parity` でも同じ失敗が出ました。

## 再現手順

```sh
./target/debug/remacs -Q --batch --eval "(prin1 (require 'shortdoc-doc))"
/path/to/emacs-31.1 -Q --batch --eval "(prin1 (require 'shortdoc-doc))"
```

期待結果（GNU）: `shortdoc-doc` を返して正常終了。
実際（Remacs）:

```text
Eager macro-expansion failure: (error "Eager macro-expansion skipped due to cycle:
  … => (load \"shortdoc-doc.el\") => (macroexpand-all (define-short-documentation-group alist …)) => (macroexpand (define-short-documentation-group …)) => (load \"shortdoc.el\") => (load \"shortdoc-doc.el\")")
```

同じ新規プロセスで先に `(require 'shortdoc)` を行う対照は、両方成功します。

```elisp
(progn (require 'shortdoc) (require 'shortdoc-doc))
```

## 調査箇所

`shortdoc-doc.el` の `define-short-documentation-group` を eager expand すると、その autoload から `shortdoc.el` をロードし、その中から再び `shortdoc-doc.el` へ到達します。GNU はこのロード順序でも成功します。Remacs の `src/lisp/load.rs` / eager expansion と autoload の循環処理、および `lisp/shortdoc.el`・`lisp/shortdoc-doc.el` の相互依存を確認する必要があります。

確認時 HEAD: `aeaff5597e60834c21d464b7ad2a4caf167726dc`、macOS/aarch64、GNU Emacs 31.1。対象実装・ライブラリに未コミット変更なし。新規プロセスでの両側比較と対照は `tests/audit_library_lifecycle_more.el`、`tests/audit/20261023/library-results.json` に保存しました。

既存 Issue は `shortdoc` の本文・タイトル検索で該当なし。#10 は深い eager expansion が実行されない問題で、既に修正済みです。本件は eager expansion 実行時の相互ロードで発生する別の再現条件です。
