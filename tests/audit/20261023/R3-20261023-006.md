現行の全テスト実行で `tests/lisp_libs2.rs` の Common Lisp 関連5テストが `void-function` で失敗します。テスト式が `cl-lib` をロードしていないことが原因です。GNU Emacs 31.1 の `-Q` でも同じ式は同じ `void-function` になります。`cl-lib` を明示 require すると、両実装とも現在の期待値を返します。

- `cl_destructuring_bind_dotted_tail`（1224行付近）

## 再現

```sh
cargo test --offline --test lisp_libs2 cl_defstruct_accepts_docstring -- --exact --nocapture
```

現在は `eval failed ... -> signal void-function (cl-defstruct)` で失敗します。他の4テストも同様に対象マクロが void です。

GNUとの切り分け例:

```elisp
(condition-case err
    (eval '(progn
             (cl-defstruct ec-probe-struct "A struct doc." one (two 2))
             (let ((s (make-ec-probe-struct :one 1)))
               (list (ec-probe-struct-one s)
                     (ec-probe-struct-two s)
                     (ec-probe-struct-p s)))) t)
  (error err))
;; requireなし: GNU/Remacs とも (void-function cl-defstruct)
;; (require 'cl-lib) の後: GNU/Remacs とも (1 2 t)
```

5テストの元の式をそのまま取り出し、新規プロセスで require 有無を比較しました。すべて require なしで両方が失敗し、require ありで両方が一致しました。

修正では、この5テストの前提に `(require 'cl-lib)` を含める必要があります。起動時に CL マクロを公開すると GNU の初期状態から外れ、修正済み #87 を戻すことになります。
