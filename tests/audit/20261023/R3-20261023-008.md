`tests/lisp_libs2.rs::compile_runs_subprocess_to_exit` は、`(accept-process-output p 2)` を一度呼んだ後すぐに `delete-process` を二度呼び、`process-status` が exit のまま、かつ `Compilation finished` が表示済みであることを期待します。しかし `accept-process-output` は出力を受け取ると子プロセス終了前にも戻るため、実行タイミングやシェルによりテスト自身が実行中のプロセスを kill し、偽の失敗になります。

## 観測

現行の全テスト実行で、`compile_runs_subprocess_to_exit` は期待 `(exit t)` に対し `(signal nil)` で失敗しました。

新規プロセスで GNU Emacs 31.1 と Remacs に同じ操作を行い、delete 前後の状態を比較しました。

| 操作 | GNU | Remacs |
|---|---|---|
| デフォルトのシェルで `echo hello-out`、一度だけaccept | `(exit exit t t)` | `(run signal t nil)` |
| `/bin/sh -c` で同じ echo、一度だけaccept | `(run signal t nil)` | `(run signal t nil)` |
| `/bin/sh -c` で `printf hello-out; sleep 0.25`、一度だけaccept | `(run signal t nil)` | `(run signal t nil)` |
| 同じ遅延コマンドを `process-live-p` で待ってからdelete | `(exit exit t t)` | `(exit exit t t)` |

値は順に「delete前のstatus、delete後のstatus、出力あり、終了メッセージあり」です。元の echo だけでも GNU 側に失敗条件があることを確認しています。

## 最小の切り分け

```elisp
(require 'compile)
(let ((shell-file-name "/bin/sh")
      (shell-command-switch "-c"))
  (compile "printf hello-out; sleep 0.25")
  (let ((p (get-buffer-process "*compilation*")))
    (accept-process-output p 2)
    (let ((before (process-status p)))
      (delete-process p)
      (delete-process p)
      (prin1 (list before (process-status p))))))
;; 両実装: (run signal)
```

テストの目的である「自然終了したプロセスに delete-process を行っても exit を保持する」を検査するには、期限付きで自然終了を待ち、終了したことを確認してから delete を検査する必要があります。
