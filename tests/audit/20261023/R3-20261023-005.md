`sqlite-open` に相対ファイル名を渡すと、GNU Emacs 31.1 は Lisp の `default-directory` を基準に DB を開きますが、Remacs は OS プロセスの作業ディレクトリに DB を作成します。別ディレクトリのバッファから相対パスで DB を開くと、意図したファイルとは違う DB にアクセスします。

## 再現手順

以下を `sqlite-directory.el` に保存し、両バイナリを同じ作業ディレクトリから実行します。作成物はコード末尾で削除します。

```elisp
;;; -*- lexical-binding: t; -*-
(let* ((dir (file-name-as-directory (make-temp-file "sqlite-dir-" t)))
       (original-directory default-directory)
       (base (concat (make-temp-name "sqlite-relative-") ".sqlite"))
       (wanted (expand-file-name base dir))
       (unwanted (expand-file-name base original-directory)) db)
  (unwind-protect
      (let ((default-directory dir))
        (setq db (sqlite-open base))
        (prin1 (list (sqlitep db)
                     (file-exists-p wanted)
                     (file-exists-p unwanted)))
        (terpri))
    (when db (sqlite-close db))
    (when (file-exists-p unwanted) (delete-file unwanted))
    (delete-directory dir t)))
```

```sh
./target/debug/remacs -Q --batch -l sqlite-directory.el
/path/to/emacs-31.1 -Q --batch -l sqlite-directory.el
```

期待結果（GNU）: `(t t nil)`。一時ディレクトリにだけ DB が作られます。
実際（Remacs）: `(t nil t)`。プロセスを起動したディレクトリに DB が作られます。

## 原因候補

`src/lisp/builtins/sqlite.rs` の `f_sqlite_open`（436行付近）は、文字列を `Connection::open_with_flags(s.borrow().as_str(), flags)` へそのまま渡しており、Emacs の `expand-file-name` 相当の処理を行っていません。

確認時 HEAD: `aeaff5597e60834c21d464b7ad2a4caf167726dc`、macOS/aarch64、GNU Emacs 31.1。対象実装に未コミット変更なし。証拠: `tests/audit_sqlite_lifecycle_more.el` の `sqlite:open-default-directory`、`tests/audit/20261023/sqlite-and-constructor-results.json`。

重複確認: SQLite 関連の既存 #162〜#167、および `sqlite default-directory` の本文検索を照合。BLOB・引数・set の遅延評価・エラー・ハンドル・空クエリの既存障害とは別のファイル名解決の問題です。
