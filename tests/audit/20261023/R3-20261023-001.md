ディレクトリを `file-notify-add-watch` で監視し、`created` 通知のコールバックから `file-notify-rm-watch` で自身を解除すると、Lisp のエラーではなく Rust の範囲外アクセスによる panic で Remacs が終了します。GNU Emacs 31.1 は `created` と `stopped` を通知し、正常に続行します。

## 再現手順

macOS/kqueue 環境で、以下を `notify-remove.el` として保存して実行します。対象は一時ディレクトリだけです。

```elisp
;;; -*- lexical-binding: t; -*-
(require 'filenotify)
(let ((dir (make-temp-file "notify-audit-" t)) watch actions)
  (unwind-protect
      (progn
        (setq watch
              (file-notify-add-watch
               dir '(change)
               (lambda (event)
                 (push (nth 1 event) actions)
                 (when (eq (nth 1 event) 'created)
                   (file-notify-rm-watch (car event))))))
        (write-region "payload" nil (expand-file-name "child" dir) nil 'silent)
        (let ((tries 0))
          (while (and (not (memq 'created actions)) (< tries 100))
            (read-event nil nil 0.02)
            (setq tries (1+ tries))))
        (prin1 (list (and (memq 'created actions) t)
                     (and (memq 'stopped actions) t)
                     (file-notify-valid-p watch)))
        (terpri))
    (when watch (ignore-errors (file-notify-rm-watch watch)))
    (delete-directory dir t)))
```

```sh
./target/debug/remacs -Q --batch -l notify-remove.el
/path/to/emacs-31.1 -Q --batch -l notify-remove.el
```

期待結果（GNU）: `(t t nil)`、終了コード 0。
実際（Remacs）: コールバック後に `index out of bounds` の Rust panic、終了コード 101。完了行まで到達しません。監視を解除しない対照は両方 `(t nil t)` で正常に完了しました。

## 原因候補

`src/lisp/builtins/filenotify.rs` の `compare_dir_list` は、`emit` から Lisp コールバックを同期実行した後も、保存した `idx` で `i.filenotify.watches[idx]` を参照します。コールバックで当該要素を削除すると、後続イベントの生成または `dir_list` 更新が範囲外になります。コールバックが別の監視を削除・追加する場合も、同じ index の意味が変わります。

確認時 HEAD: `aeaff5597e60834c21d464b7ad2a4caf167726dc`。macOS/aarch64、GNU Emacs 31.1。関連実装ファイルに未コミット変更はありません。再現テストと生出力は `tests/audit_filenotify_lifecycle.el` / `tests/audit/20261023/filenotify-results.json` に保存しました。

重複確認: open/closed の Issue を `kqueue` / `file-notify` / `ファイル監視` で検索。既存の該当障害は見つかりませんでした。
