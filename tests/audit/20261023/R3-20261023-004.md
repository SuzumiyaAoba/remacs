`make-interpreted-closure` に dotted list の ARGS を渡すと、GNU Emacs 31.1 は関数を構築し、呼び出し時に `invalid-function` を通知します。Remacs は構築時に `wrong-type-argument listp` を通知します。既存 `tests/lisp_libs2.rs::dotted_rest_lambda` が現在この違いで失敗します。

## 再現手順

```elisp
;;; -*- lexical-binding: t; -*-
(prin1
 (condition-case err
     (functionp (make-interpreted-closure '(a . b) '(a) nil))
   (error err)))
(terpri)
(prin1
 (condition-case err
     (eval '(funcall (lambda (a . b) (list a b)) 1 2 3) t)
   (error err)))
(terpri)
```

```sh
./target/debug/remacs -Q --batch -l dotted-closure.el
/path/to/emacs-31.1 -Q --batch -l dotted-closure.el
```

GNU: 一つ目は `t`。二つ目は `(invalid-function #[(a . b) ((list a b)) (t)])`。
Remacs: 両方 `(wrong-type-argument listp b)`。

`(a b . c)` の ARGS でも同様に、GNU の `invalid-function` が Remacs では `(wrong-type-argument listp c)` になります。

## 原因候補

`src/lisp/builtins/misc.rs:2020` の `f_make_interpreted_closure` が ARGS 全体を `list_to_vec()` で proper list として検証しています。GNU の構築時の CHECK_LIST は nil/cons の検査であり、dotted tail の妥当性は呼び出し時に検査されます。`parse_lambda` / `bind_lambda_walk` にある不正 arglist の呼び出し時処理へ到達する前に、constructor がエラーを返しています。

確認時 HEAD: `aeaff5597e60834c21d464b7ad2a4caf167726dc`、macOS/aarch64、GNU Emacs 31.1。関連実装に未コミット変更なし。証拠: `tests/audit_library_lifecycle_more.el`、`tests/audit/20261023/library-results.json` と `sqlite-and-constructor-results.json`。

重複確認: `make-interpreted-closure` / `dotted` で既存 Issue を検索。#20 の `func-arity` と optional なリスト引数、#70 の捕捉環境の形とは異なり、本件は dotted ARGS を構築時に過剰検証する問題です。
