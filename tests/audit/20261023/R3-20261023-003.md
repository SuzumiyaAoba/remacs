`file-notify-add-watch` でファイルを監視し、最後の監視を解除した後に新しい監視を登録すると、Remacs では新しい監視への通知が届かなくなります。登録は成功し、`file-notify-valid-p` も t のままです。GNU Emacs 31.1 は両方の登録で通知を受け取ります。

## 再現手順

macOS/kqueue 環境で以下を `notify-rearm.el` として実行します。

```elisp
;;; -*- lexical-binding: t; -*-
(require 'filenotify)
(defun notify-audit-wait (predicate)
  (let ((tries 0))
    (while (and (not (funcall predicate)) (< tries 100))
      (read-event nil nil 0.02)
      (setq tries (1+ tries)))
    (and (funcall predicate) t)))
(let ((file (make-temp-file "notify-audit-")) watch actions)
  (unwind-protect
      (progn
        (setq watch (file-notify-add-watch
                     file '(change) (lambda (e) (push (nth 1 e) actions))))
        (write-region "first" nil file nil 'silent)
        (let ((first (notify-audit-wait (lambda () (memq 'changed actions)))))
          (file-notify-rm-watch watch)
          (sleep-for 0.1)
          (setq actions nil
                watch (file-notify-add-watch
                       file '(change) (lambda (e) (push (nth 1 e) actions))))
          (write-region "second" nil file nil 'silent)
          (prin1 (list first
                       (notify-audit-wait (lambda () (memq 'changed actions)))
                       (file-notify-valid-p watch)))
          (terpri)))
    (when watch (ignore-errors (file-notify-rm-watch watch)))
    (delete-file file)))
```

```sh
./target/debug/remacs -Q --batch -l notify-rearm.el
/path/to/emacs-31.1 -Q --batch -l notify-rearm.el
```

期待結果（GNU）: `(t t t)`。
実際（Remacs）: `(t nil t)`。一度目の通知は届き、二度目は約2秒待っても届きません。新規プロセスで2回再現しました。

対照として、別の監視を一つ維持したまま上記の解除・再登録を実行すると、Remacs でも `(t t t)` になります。

## 原因候補

`src/lisp/builtins/filenotify.rs` の `f_kqueue_rm_watch` は最後の監視を除去した時に共有 kqueue FD を閉じて `KQ_FD=-1` にします。`kq_reader_loop` はこれを観測すると return しますが、`ensure_kqueue` は `KQ_THREAD_ONCE: OnceLock<()>` によって一度しか reader thread を生成しません。新しい kqueue FD が作られても、通知を回収する thread を再生成できない構造になっています。

確認時 HEAD: `aeaff5597e60834c21d464b7ad2a4caf167726dc`、macOS/aarch64、GNU Emacs 31.1。対象実装に未コミット変更なし。証拠: `tests/audit_filenotify_lifecycle.el`、`tests/audit/20261023/filenotify-results.json` と `filenotify-rearm-controls.json`。

重複確認: `kqueue` / `file-notify` / `ファイル監視` の既存 open/closed Issue を照合。#346 は通知コールバック内で解除した時の配列アクセス panic で、本件は通常の解除後に通知 reader が失われる別の障害です。
