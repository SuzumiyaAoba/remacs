何も挿入しない insert-char でも buffer-read-only が発生します。GNU は nil を返し、同じ Remacs の insert-byte COUNT=0 も nil を返します。f_insert_char がゼロ個の処理でも check_writable を呼ぶためです。

対象: `38af4d1d720760348e725dac51f8c4252c2b03d5`、macOS/aarch64。GNU Emacs 31.1 と各式を別プロセスで実行して比較。

## 追加確認: 空領域の削除

同じ問題を空領域の delete-region / delete-and-extract-region / 空バッファの erase-buffer でも確認しました。delete-char COUNT=0 は対照として GNU/Remacs とも nil です。

```elisp
(with-temp-buffer (setq buffer-read-only t) (condition-case e (delete-region 1 1) (error (car e))))
```

GNU: `(ok nil)`
Remacs: `(ok buffer-read-only)`

```elisp
(with-temp-buffer (setq buffer-read-only t) (condition-case e (delete-and-extract-region 1 1) (error (car e))))
```

GNU: `(ok "")`
Remacs: `(ok buffer-read-only)`

```elisp
(with-temp-buffer (setq buffer-read-only t) (condition-case e (erase-buffer) (error (car e))))
```

GNU: `(ok nil)`
Remacs: `(ok buffer-read-only)`

```elisp
(with-temp-buffer (setq buffer-read-only t) (condition-case e (delete-char 0) (error (car e))))
```

GNU: `(ok nil)`
Remacs: `(ok nil)`
