GNU が json-value-p で拒否する unibyte 文字列を受け入れ、元のバイトとは異なる UTF-8 を生成します。内部の代理文字が外部 JSON に漏れます。ser_value の文字列分岐で文字表現の検証がありません。

対象: `38af4d1d720760348e725dac51f8c4252c2b03d5`、macOS/aarch64、GNU Emacs 31.1 と同一コードで比較。`cargo build --offline --bin remacs` 成功。作業ツリーの既存 GUI 変更は保持しています。

## 再現

以下を `repro.el` に保存し、両実装で実行します。

```elisp
;;; -*- lexical-binding: t; -*-

;; json:utf8-serialize
(let ((print-circle t) (print-escape-newlines t))
  (prin1 (condition-case e (list 'ok (string-to-list (json-serialize (unibyte-string 195 169)))) (error (list 'error e))))
  (terpri))

;; json:invalid-utf8-serialize
(let ((print-circle t) (print-escape-newlines t))
  (prin1 (condition-case e (list 'ok (condition-case e (json-serialize (unibyte-string 255)) (error (car e)))) (error (list 'error e))))
  (terpri))
```

```sh
./target/debug/remacs -Q --batch -l repro.el
/path/to/emacs-31.1 -Q --batch -l repro.el
```
